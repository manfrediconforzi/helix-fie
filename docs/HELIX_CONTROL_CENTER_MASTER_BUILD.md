# HELIX CONTROL CENTER — CANONICAL MASTER BUILD SPEC

## Mission
Build HELIX Control Center as a production-grade Visual Operating System and visual twin of the real HELIX scientific machine. It must reveal system state, scientific evidence, agentic organization, learning, infrastructure and blockers without inventing telemetry.

## Canonical primary navigation
1. CONTROL
2. SCIENCE
3. PROOF
4. AGENTIC SYSTEM
5. LEARNING
6. BUILD & INFRASTRUCTURE

Subsections remain nested. Do not promote every module to primary navigation.

## Visual system
HELIX is dark, scientific, premium, futuristic and information-dense. Use advanced interactive diagrams when they explain structure better than cards or tables. Every section has a distinct Section DNA while remaining unmistakably HELIX.

### Section DNA
- CONTROL: nervous system / network / pulse / flow
- PATTERN LAB: DNA / constellation / mutation
- FORECASTING: time / probability cone / uncertainty
- MARKET REGIME: landscape / heat / transition
- PORTFOLIO: orbital dependencies / gravity / common risk
- PROOF: forensic gates / calibration / falsification
- AGENTS: living organization / handoffs / runtime
- LEARNING: replay / loop / evolution
- INFRASTRUCTURE: topology / pipelines / continuity
- MANUAL: process architecture / ownership / governance

## Diagram-first rule
Prefer purpose-built interactive visualizations such as network graphs, Sankey diagrams, dependency maps, causal graphs, sunbursts, radial trees, orbital graphs, heatmaps, matrices, probability cones, calibration plots, stream graphs, funnels, stage gates, state machines, topology maps, treemaps, chord diagrams, timelines, cluster maps and risk fields.

Motion must communicate flow, state, causality, dependency, risk propagation, learning or transition. Avoid decorative animation.

## Truth-first UI
Never invent data, progress, agent activity, proof results or health states.

Allowed truth states include:
- VERIFIED / HEALTHY / VALIDATED
- WARNING / PROVISIONAL
- BLOCKED / FAILED
- UNKNOWN
- UNMEASURED
- NOT CONNECTED
- INSUFFICIENT EVIDENCE

No green state without evidence.

## Global state colors
- GREEN: verified / healthy / validated
- AMBER: warning / provisional / degraded
- RED: critical / failed / blocked
- GREY: unknown / inactive / insufficient evidence
- ELECTRIC ACCENT: live activity / current execution

## Micro-description rule
Every important title, KPI, module, chart and diagram must include a tiny explanation of what it means.

## Interaction model
Where appropriate support hover, click, zoom, pan, filtering, focus, drill-down, back navigation, time/horizon selection, regime selection, pattern-family selection and status filtering.

Every selected object should answer:
1. What is it?
2. Why is it here?
3. What does it depend on?
4. What evidence supports it?
5. What is its current state?
6. What happens next?

## Drill-down
Program → System → Module → Capability → Task → Artifact → Evidence / Blocker.

## Provenance
Important metrics must expose, when available: source, calculation, timestamp, sample size, effective sample size, model version, experiment ID and evidence status.

## Science requirements
Separate prediction problems by horizon: 24H, 30D, 90D, 120D, 150D, 1Y.

Keep three probabilities distinct:
1. P(UP/DOWN)
2. P(beat benchmark)
3. P(economically attractive return)

Pattern families: PRICE, FUNDAMENTALS, MACRO, NEWS, EVENTS, INFLUENCERS, MARKET REGIME.

Maintain Historical Maximum and Robust Maximum separately.

## Proof requirements
Discovery → Validation → Blind Proof → Final Holdout → Champion.

Use walk-forward, purged validation, embargo and nested validation where appropriate. Track AUC, Brier, Log Loss, ECE, balanced/directional accuracy, coverage, effective sample size and overfitting risk. Final Holdout is protected and used rarely.

Mandatory baselines include random 50/50, always-up, always-down, historical base rate, benchmark, simple momentum and naive persistence.

## Portfolio requirements
Do not simply select the highest-scoring assets. Optimize joint behavior using dependencies, nonlinear relationships, sector/factor/macro common risk, causal diversification, tail risk, stress scenarios and calibration.

## Agentic system
Render Governor, Orchestrator, Pattern Intelligence, Probability Science, Proof / Red Team, TMLE / Learning, Portfolio Probability, Market Intelligence, Data, Infrastructure and QA as a living functional organization with ownership, inputs, outputs, dependencies, tasks, runtime state and blockers.

## Learning
FORECAST → OUTCOME → ERROR → CLASSIFY → LEARN → CHALLENGER → PROOF → IMPROVE.

TMLE must preserve point-in-time information integrity and protected proof sets.

## Infrastructure
Layerbase is the canonical HELIX database target. Do not introduce Supabase dual-write or automatic legacy import. Visualize data sources, pipelines, database, APIs, agents, schedulers, storage, deployment, backup, restore, cost, quota, incidents, single points of failure and continuity.

## Development / WIP
FOUNDATION → CONNECTIVITY → CORE EXECUTION → PROOF → LEARNING → PRODUCTION.

Use DONE, IN PROGRESS, NEXT, BLOCKED, PARKED, UNKNOWN. Never invent completion percentages.

## Acceptance
The Control Center is complete only when the six macroareas exist, section identities are clear, diagrams are interactive rather than static illustrations, drill-down and truth states work, dependencies/blockers/evidence can be inspected, and the whole site functions as one coherent HELIX operating system rather than a set of unrelated dashboards.

## Execution rule
Inspect current canonical code first. Preserve working functionality. Build real pages, not mockups. Proceed vertically: component → real page → interaction → data contract → truth states → QA. Commit every meaningful milestone and keep the repository in a working state.
